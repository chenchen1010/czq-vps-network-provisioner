# 首次交付：面板信息与个人订阅

在首次安装或把本地 YAML 交付改为原生订阅时读取。目标是管理员拿到信息就能登录，员工拿到个人链接就能导入；不要求员工复制模板或替换 UUID。

## 1. 面板登录信息必须交付

- 在 Git 忽略、权限 `600` 的 `.env.local` 保存完整 `XUI_PANEL_URL`、`XUI_PANEL_USER`、`XUI_PANEL_PASSWORD`。URL 包括 HTTPS、实际地址、端口和随机路径。
- 复用现有环境时先读取当前凭证或已有授权会话，不为交接随意重置密码。
- 验证有效 HTTPS 和真实登录；创建私人交接文件，明确这是管理员面板账号，不是员工代理账号。
- 最终回复链接到私人文件，记录验证结果。用户明确要求写入指定私密文档时可以按授权交付，但不能放进仓库、公共 README、日志、截图或公开报告。

## 2. 配置原生订阅

以下设置键在 3x-ui v3.11.0 验证过；其他版本先核对实际面板/API/官方源码，不猜接口或字段。优先通过该版本支持的面板/API 保存完整设置，避免局部请求重置其他值。确需离线 SQLite 更新时，停止服务后备份数据库、事务修改；用独立于 SSH 会话的可靠执行方式保证重新启动，回读确认结果。连接因节点重启断开时，不等于操作失败，先检查服务和持久化状态再决定是否重试。

| 设置 | 首次配置目标 |
| --- | --- |
| `subEnable` | `true`，这是订阅服务总开关 |
| `subClashEnable` | `true` |
| `subClashAutoDetect` | 支持时启用；标准 SUB 地址按客户端标识返回 YAML |
| `subJsonEnable` | 未要求其他格式时可关闭；已有业务使用时保留 |
| `subPort` / `subListen` | 选择未占用端口及合适监听地址；2096 仅为候选，不是硬编码要求 |
| `subCertFile` / `subKeyFile` | 服务器上与访问域名/IP 匹配的有效证书文件；面板有 HTTPS 不代表订阅已配好 |
| `subDomain` / `subURI` / `subClashURI` | 直接连接按实际访问地址设置；反向代理按外部 URL 配置，不能把内部监听端口当成外部端口 |
| `subPath` / `subClashPath` | 复用随机路径，避免破坏现有订阅 |
| `subClashEnableRouting` / `subClashRules` | 开启并保存不含个人节点的统一分流模板 |

保存、按版本要求重启后，检查服务、监听和**外部网络 HTTPS 下载**。防火墙/服务商安全组只放行需要的端口，不能整体关闭防火墙。证书续期必须覆盖订阅监听器的重新加载。

面板客户端信息中应出现个人 `CLASH` 或 Clash/Mihomo 行，旁边有复制按钮；`SUB` 是标准订阅，`vless://` 是单节点分享，均不要混称为已验收的 Clash 专用地址。不要把管理员登录链接给员工当订阅。

## 3. 统一分流模板与个人节点分开

```bash
node scripts/generate_clash_profile.mjs \
  --subscription-template \
  --out /secure/path/subscription-routing.yaml
```

此模式不接收分享文件，不生成 `proxies`、服务器地址或 UUID；面板根据请求的个人订阅 ID 注入该账号节点。`PROXY` 组通过 `include-all` 收集面板生成的节点，其他业务组引用它，不依赖带员工名称或剩余流量的动态节点名字。

模板包含局域网/中国大陆直连、海外社媒/YouTube/AI/其他海外代理、DNS 和关闭的 TUN。将它用于面板的全局路由配置后，必须检查实际返回内容：各版本可能只导入模板的部分字段。GeoSite/GeoIP 规则还依赖客户端数据文件；首次导入时需确认这些资源已加载，不能把已有缓存机器上的成功当成所有新设备都已验证。

不要只打开“启用路由”却留空规则，也不要把默认 `MATCH,PROXY` 当成国内外分流。不要粘贴带某个员工 `proxies` 的完整配置覆盖所有人的订阅。客户端只需导入自己的链接并选择规则模式；改流量额度通常不需要换链接，改订阅 ID 则需要重新分发。

## 4. 独立新账号验收

1. 新建明确命名的验收客户端，独立 UUID/订阅 ID，关联既有入站；额度默认可用 50 GB，记录启用状态、到期策略和初始流量。用户有指定时按指定值执行。不要覆盖旧账号或为每位员工另开入站。
2. 通过实际 API/UI 确认新账号已加入 Xray 运行配置；“数据库创建成功”不等于运行内核已应用。必要时按该版本要求重载/重启。
3. 在外部网络下载新账号的 CLASH HTTPS 订阅，不使用 `-k`。链接从私人 env/文件读取，不出现在 shell 参数、历史或公开日志中。确认节点身份属于新账号，没有其他员工 UUID；若有多个关联入站，节点数量不一定为 1。
4. 对下载内容做 Mihomo 语法检查，再用其测试副本启动独立本地端口。可改监听地址、端口、关闭 TUN、日志和必要的物理网卡绑定，不改服务器地址、UUID、Reality 参数或分流规则来“让测试通过”。
5. 实测 Google/YouTube、用户目标网站、海外出口；至少一项国内请求有 `DIRECT` 命中证据，新账号自身流量增加。403 单独标注，不声称账号登录成功。
6. 停止临时测试进程。按用户要求保留/停用验收账号并明确交接状态；未指定时保留有限额度账号并说明用途，不擅自删除，也不恢复用户主动禁用的账号。独立内核测试不代表已经给用户导入或启用系统代理。

订阅测试失败时先判断：下载失败（DNS/HTTPS/路径/服务）→ YAML 解析或资源加载失败 → 客户端未应用 → Reality 协议失败 → 目标网站策略。删除账号或更改订阅 ID 后，旧链接 404 属于身份失效，不要为了通过验收重建被用户删除的员工。

## 5. 避免本机 TUN 干扰诊断

本机已有代理/TUN 时，另起的 Mihomo 到 VPS 的连接可能再次被原代理接管。出现握手错误时：

- 对比服务器回环、原有已验收配置和新订阅的外部结果；检查到 VPS 的系统路由。
- 若旧配置也在同一测试环境失败，先排查本机路径，不能直接认定原生订阅或 Xray 版本损坏。
- 可仅对独立测试副本设置实际物理网卡 `interface-name`；先读取当前网卡，不把某台 Mac 的 `en0` 硬编码到员工订阅。
- 不在未获授权时切换用户系统代理/TUN。测试完成停止临时进程。

若用户问“服务器网络是不是坏了”，分别报告：VPS 自身 DNS/外网出口、服务和监听、公网节点链路、客户端启用/额度/有效期。本机其他代理访问正常不能证明此 VPS 节点正常；服务器能访问外网也不能证明员工账号能连。
